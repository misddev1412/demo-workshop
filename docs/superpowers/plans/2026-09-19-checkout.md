# COD Checkout Implementation Plan

**Goal:** Persist guest COD orders from the existing cart with trustworthy totals.

**Architecture:** Client form → Next.js POST route → one service-role database RPC.
Keep public validation separate from server secrets. The database owns pricing,
transactionality and idempotency; the browser owns form state and retry identity.

**Tech Stack:** Next.js 16.3, React 19, TypeScript, native fetch, Supabase/Postgres.

## 1. Contracts and API

- [ ] Add `tests/checkout.test.mjs` and `tests/checkout-api.test.mjs`; run them
  with Node's test runner and observe missing-feature failures.
- [ ] Implement `lib/checkout.ts`: validate UUIDs, 1–50 unique items, integer
  quantities 1–99, trimmed recipient name 2–100, Vietnamese phone, address 10–500,
  safe integer expected total. Normalize phone, sort items, exclude client prices.
- [ ] Implement `lib/checkout-server.ts` and `app/api/orders/route.ts`: 16 KiB
  request cap, JSON and origin validation, server-only secret, RPC timeout, map
  invalid input to 400, stale total/key conflicts to 409, upstream errors to 503.
- [ ] Verify receipt validation, no secret/error leakage, no GET order listing,
  and no upstream call for invalid requests.

## 2. Database transaction

- [ ] Add `supabase/tests/checkout.sql`, bootstrap a disposable local Postgres,
  load the existing migration, and observe failure before the new RPC exists.
- [ ] Generate a migration using Supabase CLI. Add checkout key/fingerprint,
  shipping fee and COD payment method. Implement service-only invoker RPC with
  advisory lock, current product-price locks, amount guard, and atomic inserts.
- [ ] Run SQL tests and existing access-control tests locally. Verify same-key
  concurrent requests create one order. Apply reviewed migration to the configured
  demo project and repeat rollback tests; inspect advisors.

## 3. Checkout UI and verification

- [ ] Implement `app/components/checkout-form.tsx`, integrate into `app/page.tsx`,
  and style via `app/globals.css`. Preserve the existing storefront and cart flow.
- [ ] Generate/reuse request identity from normalized data; disable concurrent
  submissions. Keep cart on failures; clear only on a validated success receipt.
- [ ] Browser-check required inputs, COD summary, failure/retry, confirmation,
  empty cart after success, and 390px layout.
- [ ] Update README and database verification notes. Run all Node tests,
  `npm run lint`, and `npm run build`; inspect final diff and server-secret isolation.
